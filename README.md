# ЗДОРОВЯКОВ

Единая торговая платформа: одно ядро, одна PostgreSQL, много витрин.
Первый канал продаж — водный-прополис.рф.

Состояние на 25.10.2026: ядро и локальная админка (этапы 2–3) реализованы.
Есть PostgreSQL-миграции, каталог/расчёт, клиенты, заказы, цены/акции, статусы,
подтверждение оплаты и аудит. Витрина и публичное оформление ещё не реализованы.

Начать новую сессию с [HANDOFF.md](HANDOFF.md) и [PROGRESS.md](PROGRESS.md).
Полное ТЗ: [docs/project/MASTER_SPEC.md](docs/project/MASTER_SPEC.md).
Отчёт: [docs/reports/STAGE_03_REPORT.md](docs/reports/STAGE_03_REPORT.md).
Админка: [docs/project/ADMIN.md](docs/project/ADMIN.md).

## Локальные проверки

Нужен Node.js 24.x. Установка из lockfile:

```sh
npm ci
npm test
npm run build
```

`npm test` проверяет структуру, TypeScript, денежные расчёты и интеграцию с настоящим
изолированным PostgreSQL 18.4. Нужен запуск локальных native binaries.
Если npm блокирует install scripts, использовать штатное одобрение (не обходить
политику). В CI PostgreSQL запускается отдельным disposable service.

В трёх терминалах, из корня проекта:

```sh
npm run db:local
# БД остаётся в первом терминале. Во втором:
npm run db:migrate
npm run dev
# В третьем: GET http://127.0.0.1:3000/health/ready
```

`db:local` создаёт dev-БД на 127.0.0.1:55432, генерирует случайный пароль в
игнорируемом tmp/local-db.env и сохраняет данные после остановки. Системная служба
не создаётся. Для уже доступной БД задать DATABASE_URL в локальном .env и
не запускать db:local. Существующий tmp/local-db.env имеет приоритет над .env;
для внешней БД использовать CLI с DATABASE_URL окружения или отдельный checkout.
Перед миграциями обязательно проверить целевую БД; production требует согласования.

API и примеры запросов: [docs/project/API.md](docs/project/API.md).
`npm run audit:local`
`audit:local` показывает только ОС, версии инструментов и наличие команд;
не читает секреты, домашние каталоги, БД и конфигурации других проектов.

## Структура

```text
apps/api/                  центральный backend
apps/worker/               обработчик очереди (этап 6)
apps/admin/                локальная центральная админка
apps/storefront/           первая витрина (этап 4, после согласования макета)
packages/contracts/        публичные JSON Schema и DTO
db/migrations/             последовательные SQL-миграции
infra/                     конфигурация окружений и эксплуатация
scripts/                   локальные проверки
tests/                     план проверок и будущие тесты
docs/project/              ТЗ, архитектура, схема, решения, состояние
docs/reports/              отчёты этапов и контрольные точки Git
```

## Git

Репозиторий: https://github.com/Diamondberg/zdorovyakov.git.
`main` — пустая исходная точка; вся разработка — `feature/zdorovyakov-mvp`.
После этапа: проверки, отчёт, commit, push, сверка удалённого SHA.
Слияние в main и публичное развёртывание требуют разрешения владельца.

Перед вёрсткой сначала нарисовать визуальный макет и согласовать его с владельцем.
Не подключать реальных покупателей и платные сервисы в ходе локальной разработки.
