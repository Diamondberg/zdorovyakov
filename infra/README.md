# Инфраструктура

Production-сервер и его проекты не обследованы: адрес и доступ не предоставлены.
Ничего не устанавливать на предполагаемый сервер по одному DNS-адресу.

Целевая схема: Linux в согласованном регионе РФ, reverse proxy с TLS,
Node API и worker, закрытый PostgreSQL, статические витрины и админка.
Выбор Nginx/Caddy после проверки существующего сервера; DNS не изменять.
На этапе 2 подготовлено локальное окружение PostgreSQL 18.4 и npm lockfile.
`npm run db:local` — SCRAM/случайный пароль, порт 55432 только 127.0.0.1,
данные и credentials в игнорируемом tmp/. Системные службы не создаются.
CI использует postgres:18 как отдельную disposable service; тесты с внешней
TEST_DATABASE_URL допускают только новую loopback-БД zdorovyakov_test.
Docker сейчас в PATH не обнаружен; не считать его установленным.

Перед запуском: проверить доступы и ресурсы, изоляцию БД, секреты, логи без ПДн,
TLS, реальные SMTP SPF/DKIM/DMARC, резервирование и восстановление на отдельной БД.
План резервирования: pg_dump custom format, шифрованное отдельное хранилище,
срок хранения по утверждённой политике, регулярная проверка восстановления.
RPO/RTO согласовать с владельцем. Бэкапов и выполненного restore пока нет.
См. https://www.postgresql.org/docs/current/backup-dump.html.
