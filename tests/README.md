# Проверки

`npm test`: каркас → typecheck → 11 unit-проверок → 10 PostgreSQL/API-сценариев.
`npm run build`: компиляция TypeScript и копирование SQL для скомпилированного runner.
Все контакты в fixtures синтетические, с доменом .invalid; реальные данные не нужны.

Реализованные проверки этапа 2:
- Миграции на реальном PostgreSQL: чистое применение, повтор, ограничения и транзакции.
- Цены в копейках: 1=47000, 3=141000, 6=253800, 9=359550.
- Границы 5/6/8/9; до начала, в момент начала и окончания акции; неактивная акция.
- Ошибочные количества; игнорирование подменённой цены клиента.
- Публичный каталог без закупочных цен; изоляция и allowlist витрин.
- Конкурентная идемпотентность заказа, снимки цен и outbox в одной транзакции.
- Полный rollback при ошибке вставки outbox; конкурентная идентификация email;
  несколько товаров; CORS, rate limit, readiness и настоящий HTTP на loopback.

По умолчанию создаётся новый PostgreSQL-кластер в OS temp со случайными
учётными данными, loopback/SCRAM; после тестов сервер останавливается.
Синтетические данные остаются в уникальном temp-каталоге; автоматического
рекурсивного удаления нет. Это не резервная копия рабочей БД.
Windows native binaries запускаются через короткие ASCII-пути; это исправляет
ошибку initdb UTF8 в кириллическом пути без изменения системной кодировки.

В CI TEST_DATABASE_URL указывает на новую loopback-БД zdorovyakov_test;
тесты отклоняют другое имя/хост или БД с существующими public-таблицами.
CI использует postgres:18 service и npm ci --ignore-scripts.

повторные покупки, экспорт с защитой CSV-формул, мобильный сценарий и восстановление БД.
