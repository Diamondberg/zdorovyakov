# API этапа 2

Локально: http://127.0.0.1:3000. Запуск — README.md. Денежные значения в копейках RUB.
Это центральное API, не отдельная БД лендинга. Frontend не реализован.

| Метод | Маршрут | Результат |
|---|---|---|
| GET | /health/live | Процесс отвечает |
| GET | /health/ready | БД доступна и начальные миграции применены; иначе 503 |
| GET | /api/v1/storefronts/:slug | Публичные id, slug, name, domain активной витрины |
| GET | /api/v1/storefronts/:slug/products | Только активные товары, явно назначенные витрине |
| POST | /api/v1/storefronts/:slug/quote | Серверный расчёт нескольких товаров, скидки и суммы |
| OPTIONS | /api/v1/storefronts/:slug/* | CORS preflight для разрешённого origin |

Первый slug: `vodny-propolis`. Сначала GET products, затем взять его productId:

```json
{
  "items": [
    { "productId": "<UUID из каталога>", "quantity": 6 }
  ]
}
```

От 1 до 50 уникальных товаров, количество от 1 до 999. Дубли productId, дробные
количества, неизвестные поля (включая подменённую цену) отклоняются. Разрешён только
ассортимент выбранной активной витрины. Никаких purchase/cost полей в ответах.

Ответ quote содержит lines, subtotalMinor, discountMinor, itemsTotalMinor,
shippingMinor и totalMinor. Пока доставка неизвестна, последние два равны null,
сообщение — «Стоимость доставки уточняется». 0 не используется вместо неизвестного.
Акция по умолчанию отсутствует: 6 флаконов = 282000 копеек, 9 = 423000.
После задания реальных дат скидки применяются только при startsAt <= DB time < endsAt.

Сервер определяет время и цену. Округление каждой единицы до копейки half-up,
затем умножение на количество. Истёкшая/отключённая акция перестаёт применяться.
Пересекающиеся активные акции для одного товара отклоняются внутренним сервисом
под advisory lock; при некорректной конфигурации в БД quote выдаёт 503.

Origin должен точно совпадать с allowed_origins витрины. В seed только HTTPS
punycode-имя первого домена. Это защита браузерного доступа, не механизм
авторизации: публичный каталог доступен серверным клиентам без Origin.
Нет cookies и авторизованных публичных методов на этапе 2. Лимит — 120 запросов
в минуту на IP/процесс, body <=16 KiB, reverse proxy пока не доверяется.
API слушает loopback по умолчанию. CORS localhost добавлять только явной конфигурацией
БД в dev, не включать wildcard в production.

Ошибки: `{ "error": "CODE" }`, без SQL/стека/ПДн. Основные коды:
INVALID_REQUEST (400), PRODUCT_NOT_AVAILABLE / STOREFRONT_NOT_FOUND (404),
ORIGIN_NOT_ALLOWED (403), RATE_LIMITED (429), PROMOTION_CONFIGURATION_CONFLICT (503).

## Внутренние сервисы (не HTTP endpoints)

- savePromotion: имя, даты, товары, пороги, активность и досрочное отключение;
  аудит и проверка пересечений. Этап 3 подключит авторизованную админку.
- createOrder: доверенный результат email-проверки, снимки получателя и адреса,
  серверный перерасчёт, идентификация по подтверждённому email, отдельный customer_id,
  три независимых начальных статуса, строки, order event и outbox в одной транзакции.
- UUID idempotency key + хеш нормализованного содержания: конкурентные повторы
  возвращают тот же заказ; другое содержание с тем же ключом даёт 409.
- Телефон приводится к +7, не подтверждается и не объединяет клиентов.

Публичных POST /orders, чтения истории по email и админских маршрутов пока нет.
Не делать маршрут, принимающий `verifiedEmail` от браузера: на этапе 5 результат
проверки должен поступать из одноразового защищённого серверного механизма.
Outbox только записывается; почтовый worker и реальная отправка — этап 6.
